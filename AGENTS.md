# Smithy plugins

* User-facing documentation lives under [`docs/`](docs/). Update those guides when behavior or integration steps change.
* **Scala 3.3.6** with strict compiler options (`-Werror`, `-Wunused:all`, `-Wvalue-discard`, `-deprecation`, `-feature`, `-unchecked`, `-no-indent`). Use **`{ }` brace syntax** only — do not use `:`/`end` optional-brace blocks or significant-indent `then`/`do` forms.
* **Cats Core 2.12.0** and **Cats Effect 3.7.0** on all modules (`cats-core` is explicit on `smithySqlPlugin`). Use **`ValidatedNel[SqlSchemaError, *]`** (`SqlValidated`) with `mapN` / `traverse` for Smithy model and plugin-config validation; convert to exceptions only at the Smithy build plugin boundary (`SmithyStacheBuildPlugin`). Do not use `for` on `Validated` (fail-fast). Synchronous extraction does not use `IO`.
* **Always use `sbtn`** (SBT thin client) from this repository root; never run plain `sbt` or `coursier launch org.scala-sbt:sbt-launch:…`. Examples: `sbtn smithySqlPlugin/test`, `sbtn publishM2`.
* Assume **`sbtn` is on `PATH`** (one-time install, e.g. `coursier install sbtn`). Do not wrap every command with `export PATH="$HOME/.local/share/coursier/bin:$PATH"` or bootstrap SBT through Coursier per invocation.
* Mustache template golden tests live under `sql-plugin/src/test/resources/mustache-template-tests/<test-name>/` (`smithy/smithy-files.smithy`, src under `<language>/src/<service-type>/...`, tests under `<language>/test/<service-type>/<implementation>/`, optional `unsupported.md` under `<language>/src/<service-type>/<implementation>/`). Subclass [`MustacheTemplateTestSuite`](sql-plugin/src/test/scala/com/jacoby6000/smithy/mustachetest/MustacheTemplateTestSuite.scala) with one or more [`MustacheTemplateLanguageBackend`](sql-plugin/src/test/scala/com/jacoby6000/smithy/mustachetest/MustacheTemplateLanguageBackend.scala) implementations identified by [`MustacheTemplateVariant`](sql-plugin/src/test/scala/com/jacoby6000/smithy/mustachetest/MustacheTemplateVariant.scala); see [`SqlServiceCodegenMustacheTemplateTestSuite`](sql-plugin/src/test/scala/com/jacoby6000/smithy/sql/codegen/SqlServiceCodegenMustacheTemplateTestSuite.scala). For `@sqlService` Python DB backends, golden-test shared `db/model/*_models.py` and `db/*_protocol.py` once under `python/src/`, plus per-implementation `*_aiosqlite.py` / `*_psycopg.py` and `test_*_derived_sql.py` under `python/test/` when derived insert + select-one exist.
* `sql-service-codegen` renderer tests run strict **mypy**, **pyright**, and **pytest** on generated Python via an ephemeral uv workspace under `sql-plugin/target/sql-service-codegen-python-workspace/` (`PythonCodegenWorkspace`; `uv sync --frozen` once per test JVM; removed by `sbtn smithySqlPlugin/clean`; requires `uv` on `PATH`). Workspace config lives in [`sql-plugin/src/test/resources/sql-service-codegen-python-workspace/`](sql-plugin/src/test/resources/sql-service-codegen-python-workspace/).
* Integration test modules are top-level siblings: `sql-plugin-common-it`, `sql-plugin-postgres-it`, `sql-plugin-sqlite-it` (not nested under a single parent folder).
* `sql-plugin-common-it` is a shared library for dialect IT modules: fixtures and JDBC helpers go in **`src/main`** (Compile). Only tests and helpers not used by other modules go in its `src/test`.
* `sql-plugin-postgres-it` and `sql-plugin-sqlite-it` are dialect integration-test modules: **only** `src/test` (standard `Test` configuration). Do not add `src/it`, `IntegrationTest`, or `src/main`. Dialect-specific helpers belong in the matching module’s `src/test`.
* Published plugin JARs are consumed by `smithy build` via Maven coordinates in consumer `smithy-build.json` files (see [`docs/integration.md`](docs/integration.md)). SQL configuration uses the `smithy-stache` plugin key with a `sql` object: dialect keys (`sqlite`, `postgres`) take `enable` (default `false`) and `migrationLocation`; `languageTargets` is a `Map<String, LanguageTarget>` where each entry takes `sourceOutputDir`, `testOutputDir`, and optional `templateDirectory`. Only `python` has bundled templates (`classpath:sql-service-codegen/python`); other languages require an explicit `templateDirectory` whose classpath contains every template required by enabled dialects. Bundled codegen templates are inferred from enabled dialects — do not require per-artifact `artifacts` entries in `smithy-stache`.
* `@sqlService` interface/model codegen uses Scalate Mustache templates under `sql-plugin/src/main/resources/sql-service-codegen/`; configure outputs in `smithy-stache.sql.languageTargets` (see [`docs/integration.md`](docs/integration.md) and [`sql-plugin/README.md`](sql-plugin/README.md)).
* Use functional programming patterns and leverage the abstractions provided by cats and cats-effect where applicable.
* Avoid side-effects where possible. Favor immutable structures. Local mutations are fine as long as they don't escape their scope.  Mutations for working with the smithy model are also acceptable
