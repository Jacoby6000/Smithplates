# Smithy plugins

* User documentation lives under [`docs/usage/`](docs/usage/). Contributor documentation lives under [`docs/contributing/`](docs/contributing/). Update the relevant tree when behavior or integration steps change.
* **Scala 3.3.6** with strict compiler options (`-Werror`, `-Wunused:all`, `-Wvalue-discard`, `-deprecation`, `-feature`, `-unchecked`, `-no-indent`). Use **`{ }` brace syntax** only — do not use `:`/`end` optional-brace blocks or significant-indent `then`/`do` forms.
* **Cats Core 2.12.0** and **Cats Effect 3.7.0** on `smithyStacheTestkit` and dialect IT modules (`smithySqlPostgresRendererIt`, `smithySqlSqliteRendererIt`). Use **`ValidatedNel[SqlSchemaError, *]`** (`SqlValidated`) with `mapN` / `traverse` for Smithy model and plugin-config validation; convert to exceptions only at the Smithy build plugin boundary (`SmithyStacheBuildPlugin`). Do not use `for` on `Validated` (fail-fast). Synchronous extraction does not use `IO`.
* **Always use `sbtn`** (SBT thin client) from this repository root; never run plain `sbt` or `coursier launch org.scala-sbt:sbt-launch:…`. Examples: `sbtn smithyStachePlugin/test`, `sbtn smithySqlIr/test`, `sbtn publishM2`, `sbtn scalafmtCheckAll`, `sbtn 'scalafixAll --check'`.
* CI (`.github/workflows/ci.yml`) runs on push/PR to `main`: `scalafmtCheckAll`, `scalafixAll --check`, `compile`, unit tests on all `modules/` projects, and Docker-backed `smithySqlPostgresRendererIt/test` + `smithySqlSqliteRendererIt/test`. Requires **Java 11**, **sbtn** (via Coursier), **uv**, and **Docker** on the runner.
* Git pre-commit hooks (`.pre-commit-config.yaml`, `scripts/pre-commit-scala.sh`): after `pre-commit install`, commits touching `*.scala`/`*.sbt` run `scalafmtAll`, `scalafixAll`, then `compile`. Re-stage if fmt/fix modify sources.
* Assume **`sbtn` is on `PATH`** (one-time install, e.g. `coursier install sbtn`). Do not wrap every command with `export PATH="$HOME/.local/share/coursier/bin:$PATH"` or bootstrap SBT through Coursier per invocation.
* **Module layout** under `modules/`:
  * `smithy-sql-ir` — schema ADTs, table extraction (`SqlIrExtractor`), shared DDL primitives
  * `smithy-sql-service-ir` — query/service IR (`SqlServiceIr`), extractors
  * `smithy-sql-service-query-renderer` — `SqlQueryRenderer` trait, `SqlParameterizedStatement`, dialect-neutral query rendering
  * `smithy-sql-service-query-renderer-postgres` / `smithy-sql-service-query-renderer-sqlite` — dialect `SqlQueryRenderer` implementations
  * `smithy-sql-sqlite-renderer` / `smithy-sql-postgres-renderer` — dialect schema DDL only (`SqlSchemaDdlRenderer`); depend on `smithy-sql-ir` only
  * `smithy-sql-service-renderer` — Mustache/Scalate, bundled Python templates, Python-specific codegen in `codegen.python`; compile depends on query-renderer base only
  * `smithy-stache-plugin` — thin Smithy build plugin; wires DDL and query renderers; **only published** artifact (`com.jacoby6000:smithy-stache-plugin`)
  * `smithy-stache-testkit`, `smithy-sql-postgres-renderer-it`, `smithy-sql-sqlite-renderer-it` — testkit + dialect integration tests
* Mustache template golden tests live under `modules/smithy-sql-service-renderer/src/test/resources/mustache-template-tests/<test-name>/` (`smithy/smithy-files.smithy`, src under `<language>/src/<service-type>/...`, tests under `<language>/test/<service-type>/<implementation>/`, optional `unsupported.md` under `<language>/src/<service-type>/<implementation>/`). Subclass [`MustacheTemplateTestSuite`](modules/smithy-sql-service-renderer/src/test/scala/com/jacoby6000/smithy/stache/mustachetest/MustacheTemplateTestSuite.scala) with one or more [`MustacheTemplateLanguageBackend`](modules/smithy-sql-service-renderer/src/test/scala/com/jacoby6000/smithy/stache/mustachetest/MustacheTemplateLanguageBackend.scala) implementations identified by [`MustacheTemplateVariant`](modules/smithy-sql-service-renderer/src/test/scala/com/jacoby6000/smithy/stache/mustachetest/MustacheTemplateVariant.scala); see [`SqlServiceCodegenMustacheTemplateTestSuite`](modules/smithy-sql-service-renderer/src/test/scala/com/jacoby6000/smithy/stache/sql/codegen/SqlServiceCodegenMustacheTemplateTestSuite.scala). For `@sqlService` Python DB backends, golden-test shared `db/model/*_models.py` and `db/*_protocol.py` once under `python/src/`, plus per-implementation `*_aiosqlite.py` / `*_psycopg.py` and `test_*_derived_sql.py` under `python/test/` when derived insert + select-one exist.
* `sql-service-codegen` renderer tests run strict **mypy**, **pyright**, and **pytest** on generated Python via an ephemeral uv workspace under `modules/smithy-sql-service-renderer/target/sql-service-codegen-python-workspace/` (`PythonCodegenWorkspace`; `uv sync --frozen` once per test JVM; removed by `sbtn smithySqlServiceRenderer/clean`; requires `uv` on `PATH`). After golden comparison, `PythonCodegenWorkspace` runs generated integration tests with `pytest -m integration` on each rendered `test_*_derived_sql.py` file. Postgres variants require Docker (`testcontainers.postgres.PostgresContainer`); SQLite variants use in-memory `aiosqlite`. Workspace config lives in [`modules/smithy-sql-service-renderer/src/test/resources/sql-service-codegen-python-workspace/`](modules/smithy-sql-service-renderer/src/test/resources/sql-service-codegen-python-workspace/).
* `smithy-stache-testkit` holds shared Smithy fixtures and JDBC DDL helpers (`src/main`). Dialect renderer IT modules (`smithy-sql-postgres-renderer-it`, `smithy-sql-sqlite-renderer-it`) contain **only** `src/test`.
* Published plugin JARs are consumed by `smithy build` via Maven coordinates in consumer `smithy-build.json` files (see [`docs/usage/integration.md`](docs/usage/integration.md)). SQL configuration uses the `smithy-stache` plugin key with a `sql` object: dialect keys (`sqlite`, `postgres`) take `enable` (default `false`) and `migrationLocation`; `languageTargets` is a `Map<String, LanguageTarget>` where each entry takes `sourceOutputDir`, `testOutputDir`, and optional `templateDirectory`. Only `python` has bundled templates (`classpath:sql-service-codegen/python`); other languages require an explicit `templateDirectory` whose classpath contains every template required by enabled dialects. Bundled codegen templates are inferred from enabled dialects — do not require per-artifact `artifacts` entries in `smithy-stache`.
* `@sqlService` interface/model codegen uses Scalate Mustache templates under `modules/smithy-sql-service-renderer/src/main/resources/sql-service-codegen/`; configure outputs in `smithy-stache.sql.languageTargets` (see [`docs/usage/integration.md`](docs/usage/integration.md) and [`modules/smithy-stache-plugin/README.md`](modules/smithy-stache-plugin/README.md)).
* Use functional programming patterns and leverage the abstractions provided by cats and cats-effect where applicable.
* Avoid side-effects where possible. Favor immutable structures. Local mutations are fine as long as they don't escape their scope.
